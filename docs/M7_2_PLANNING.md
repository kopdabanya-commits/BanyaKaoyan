# M7.2：学习检测与规划预览

本阶段沿用 #53 的思考助手和 #54 的私人档案，叠加在独立 ECS 工程清理 PR 上。这里只增加学习分析和规划**建议**，没有 M7.3 自动执行、定时调用、生产部署或真实档案导入。

## 日常入口与费用

原 PWA 设置「学习助手 → 学习诊断」共用一套两科界面。先尝试核对手机同步，再读取只读检测；同步不成功时明确只代表云端现有数据。显示近7/14天记录、最重要的1–3项提示、依据、题型记录、未来负荷和未知项，其余提示折叠，不占首页。

查看、刷新、切科、统计、打卡和普通同步均不调用模型。进入思考助手只是打开表单，主动发送、数据分享同意、有效密钥/开关/预算仍需同时满足。日、周、阶段模式使用已有 high 思考和调用上限；本阶段测试全部禁用或模拟提供商，没有真实费用。轻量/高强度分级仅预留标记，没有新增后台多模型循环。

M7.2 返回结构化分析及计划前后对照，**不显示执行按钮**；即使手工调用原提交接口，服务器也返回 `planning_preview_only`。原 M6 普通讨论的明确人工确认路径保留，但新增可靠预算及硬约束校验。模型不能修改档案、代码、权限、部署或历史记录。

## 确定性检测

`learning_analysis.py` 不依赖提供商。`AnalysisRequest` 支持科目、分析日期、预期快照/档案版本。`POST /v1/ai/analysis` 或允许列表 `learning.detect@1` 读取。

窗口按**任务所属日期**选择，明确不代表实际学习发生日。区分计划、打卡、不做、有记录和未记录；历史档案不加入记录计数，未打卡不等于没学习。没有模板覆盖的未来日期标未知，不当作0分钟空闲。

检测包括：

- 近7/14天按题型的记录、完成、不做及训练分布；阅读二刷按明确轮次标题单独分类。
- 成对保存的预计/实际总时长及样本数；没填实际时间返回 null，不补零。
- 真实错题数及样本数。仅在任务明确有 `questionCount`、错题范围有效、每个比较窗口至少3项且总题数至少15时计算错误率。现有多数任务没有这个元数据，因此通常显示未知；不从题型、标题或题号猜分母，也不拿政治题库历史进度当训练正确率。
- 有充分样本时比较两周错误率；不预测考试分数、掌握程度或没有证据的整体进度。
- 未来7天负荷、课程上限、题感练习缺失、旧任务状态积压、目标与超负荷的协调提示、题型缺少训练证据、过期档案、缺失/过少记录和用时、可能过期的云端快照。
- 实际课程任务总时长超过上限时提醒核对，明确不推断其中真正的视频观看时间。

每项 issue 含 issueCode、subject、severity、dateRange、evidence、sourceRefs、sampleSize、confidence、recommendedAction、requiresAI。`sourceTaskIds`、快照/档案版本、模板哈希与分析日期可追踪依据；结果 fingerprint 由来源版本生成。没有服务器分析缓存，重新读取即重新计算，不能把旧结果当新事实。

## 可用时间与硬约束

`learning_policy.py` 从 M7.1 当前、有效、已确认/报告的结构化条目读取政策，不解释任意聊天文字为执行权限。

- `budget` 类 `value.minutes` 是个人建议预算；英语默认非单词，政治默认总时间。单词单独统计，不重复添加。未知预算不回退到135，也不把预设模板时间或旧同步默认设置当作本人确认。
- 日规划可提供本次 `availableMinutes`，只作用目标日，不更新长期档案。周规划需要可靠的长期预算；预算未知时可做阶段分析，精确规划或带改动的建议会拒绝。
- `constraint` 类明确确认后可设置 `value.rule`：daily_limit、course_limit、daily_practice、no_carry_all；数值上限必须填写分钟。档案编辑的折叠区可选规则与范围，普通文字限制仍送入上下文但不冒充可执行结构化条件。
- 服务端验证每日硬上限、课程上限及英语每日题感要求；修改和改期会检查原日与目标日。M7.2 还验证建议预算，不能绕过原私人计划安全上限。原 M6 人工路径和 GPT Action 的计划预览/提交也验证当前结构化硬约束。
- 档案更新递增 revision。旧规划预览和已完成的诊断收据在查询时核对档案、快照、模板、日期和有效期，变化后标冲突或过期，不能继续执行。

建议预算和硬上限分开：预算用于规划可行性，硬规则是服务端强制条件。不同语义的规则应使用稳定 key 修正，旧版本保留；自然语言不能自动变成规则。

## 三种规划与结构化结果

`learning_planner.py` 提供 `PlanningRequest`、`prepare`、`PlanningSuggestion`、`validate_suggestion`。

| 模式 | 主要上下文 | 建议边界 |
| --- | --- | --- |
| day | 目标日±1天、近况汇总、有效规则 | 最多3项局部改动，可用临时当天分钟 |
| week | 未来7天任务、最近7/14天汇总 | 最多7项，保留大部分计划，不重复新增练习 |
| diagnosis | 最近14天聚合、必要未来任务 | 可以只分析，至多3项可选建议 |

`POST /v1/ai/planning/prepare` 免费、只读，返回 context、analysis、sources、fingerprint、previewOnly。`learning.planning.prepare@1` 是相同实现的只读能力。

现有 `/v1/ai/chat` 增加 planningMode、targetDate、availableMinutes 可选参数，复用原高思考、费用预留、幂等及查询流程，使用严格 JSON：summary、findings、evidence、uncertainties、recommendations、proposedChanges、reasons。每项建议必须有理由和真实允许来源；缺少数据时不能省略不确定性说明。

建议先经过原 `private_plan.apply_patch` 的副本预览，再校验已完成/不做保护、不可写字段、日期范围、时间约束、重复/无效改动和整批堆积。操作仅允许受限 update/add，没有 SQL、删除或全量快照替换。建议收据存入已有 `ai_requests`，没有第二套学习数据库；没有提交备份或快照写入，因为 M7.2 不执行。

## 上下文、隐私和兼容

复用 M7.1 分层、题型相关性、来源和字节预算。规划附加确定性检测结果；先裁剪旧对话与背景，再压缩重复任务 ID 和次要提示。安全规则、有效硬约束、必要任务和来源版本放不下时返回413，不降低保护条件。摘要仅沿用预留结构，不生成或保存内部思考。

所有者本地诊断可见错题数量，但传模型仍受额外分享授权控制：未勾选时移除检测汇总中的错题和错误率字段/提示，复盘正文同样不发。无授权跨科仍不读取另一科。模型不能自行保存偏好；本人必须在档案入口确认。

增加两项只读能力，沿用实际模型生成的输入契约、固定实现映射、版本/撤销检查。无自动写权限。档案 schema 1 仅增加可选规则/范围字段，旧档案保持可读，不重建数据库；快照协议、存储键和 PWA 安装身份不变。

## 测试与模拟结果

所有检测和模型测试均使用合成记录，费用请求由 fake provider 注入。本地手机尺寸 Chromium 连接真实后端代码，验证两科诊断、进入思考、结构化结果和预览：无横向溢出/页面异常，M7.2 没有提交按钮，前后学习快照相同。

合成英语例：14项阅读记录，7/14天窗口分别有7/14项完成；有明确题目总数的合成样本提示错误率变化、实际时间超过预计。非单词建议预算38分钟、单词37分钟独立；模拟把目标日阅读18改22分钟，预览通过，没有执行。此处数字不是用户记录。

合成政治例：建议预算62分钟、课程上限27分钟；未来课程35+刷题25引发课程提示。模拟把课程改为26，合计51分钟的预览通过；改成31则拒绝课程超限。另有60分钟参数化回归，证明预算从档案读取，没有135默认回退。政治缺少逐任务总题数，错误率未知。

本地完整回归：143 项 Node、121 项 Python（含7项 ECS 包/回滚）通过；计划镜像、语法、隐私和完整 ECS 静态包检查通过。CI 结果另见本阶段 PR 验收记录。既有 Starlette TestClient 弃用提示不影响通过；真正 Android 设备、生产迁移/发布、真实 DeepSeek 接口与计费未验收。Cloudflare 外部检查不属于 M7.2 必要验收，不继续排查，关闭步骤见 ECS_RELEASE.md。
