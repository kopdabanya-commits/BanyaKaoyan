# 用 DeepSeek 思考模式讨论学习计划

普通 ChatGPT 项目对话没有私人服务器工具。M6 开发版把日常入口放进原来的板牙考研 PWA「设置 → 学习助手」，使用 DeepSeek API 思考模式。仍是同一个软件、服务器和数据库，不需要私人 GPT、第二个 App 或每次改 GitHub。

**本次只开发与测试，尚未部署或启用付费请求。** 用户选择先开发，待安全配置密钥与费用上限后再启用。没有调用真实模型、创建授权钥匙或修改生产学习记录。

## 日常怎么用

1. 选英语二或政治，再选需要讨论的日期范围，默认约两周，最多 31 天。发送前手机先同步；有离线新记录或冲突时停下。
2. 说出想法，例如“结合这几项练习的实际用时，看看下周是否太满”。首次发送前确认所选数据会发送给 DeepSeek 并按用量计费。错题数、题号与复盘内容默认不发，需要时单独勾选。
3. DeepSeek 用思考模式分析，先给建议。普通讨论不写计划；涉及调整时，服务器验证后显示修改前后的任务、日期、说明和预计用时。
4. 核对后点“确认同步”。服务器再次检查版本、保护已完成与不做任务，先在同一事务备份原快照，再改指定私人计划覆盖层。手机收取更新前保留本机恢复副本；两边都有新变化则停止。
5. 想继续调整就继续说，不用找工程人员。建议十分钟后过期，记录或模板变化也会使旧建议失效。结果不明先点“查询本次结果”，不会再次调用模型或重复写入。

界面中的模型文字不是执行凭证。只有服务器 `applied` 收据表示云端提交成功；手机是否接收需另行核对。模型说“已同步”也不能触发写入。

## 谁负责什么

| 事情 | 负责入口 |
| --- | --- |
| 讨论学习安排、分析已授权的实际记录 | App 内学习助手，DeepSeek 思考模式 |
| 确认是否采用建议 | 用户看过具体改动后确认 |
| 备份、版本校验、保护学习记录、写入私人覆盖层 | 原有华为云后端 |
| 修 Bug、改界面、服务器维护、审核和发布代码 | 工程对话／受限开发 agent，沿用 PR 与 Actions |

学习助手没有 SSH、GitHub 或执行命令的工具。它不能管理服务器、替换整个快照、改打卡/不做、删除历史记录或读取其他科目数据。原私人 GPT Action 保留为可选高级接入与撤销入口，不再作为日常必需条件。

## 思考模式和算力控制

已核对 2026-10-18 的官方文档：模型 `deepseek-flash`，显式 `thinking.type=enabled`、`reasoning_effort=high`。每次最多 8192 个生成 token，用于思考和最终结果，不自动扩容或重试；输入最多 32 KB，最多 100 项任务。使用 JSON 输出，只提结构化建议，不启动多轮自主工具循环、联网搜索或后台付费任务。

每次只带最近六条对话及当前范围的最新服务器记录。更换科目、日期、分享范围会清空对话，避免把英语内容带进政治或保留已撤销分享的信息。内部思考内容不写入后续上下文、界面或数据库，保留给用户看的结论和建议。遇到长对话需要重复确认长期约束，首版不承诺永久记忆。

公开预设文字不能证明用户实际完成情况，因此不向模型传入默认计划的历史叙述。上下文使用任务日期/标题/类型/预计用时、真正保存的完成状态和实际时间，以及私人计划说明。没有填写的值不推断。实际完成日期没有独立记录，不能拿任务日期冒充。

## 隐私与费用边界

- 手机只用已有云同步认证向自己的服务器请求；DeepSeek API key 只放服务器受保护的配置，绝不放进前端、聊天、公开参数或日志。全量同步密钥、SSH 和其他凭据不会发送给模型。
- 原始聊天正文只在本次页面内存中携带；服务器保存请求哈希、受限建议、结果及预算预留，以便超时查询和防重复。手机 `sessionStorage` 仅留请求 ID、科目和日期，用来重开页面查询，不保存对话或 API key。
- 所选数据会离开自有服务器并交给 DeepSeek 处理，不能说成全部留在华为云。发送前必须主动勾选同意；复盘与错题需额外勾选。不要向聊天粘贴任何密钥，服务器也会拦截常见凭据样式。
- 除了发送消息，不会调用付费模型。查看状态、查询结果和确认已有建议不会再调用模型。请求超时或返回不完整时保留预算预留，不自动重复收费请求。
- 每月调用次数上限默认 100 次；预算默认 **0**，默认关闭。代码要求启用标志、有效密钥和正预算都具备才允许模型请求。
- 应用按输入字节上界及完整 8192 输出 token、缓存未命中和高峰单价保守预留。当前配置为每百万输入 $0.30、输出 $1.20；这不是实际账单，也不是服务商硬限额。价格变动、汇率或其他程序共用账户不受应用控制，启用前重新核对官方单价与账户额度；建议独立密钥便于撤销。

## 后续怎么启用（本次不执行）

1. 审阅本 PR，确认真实 API 调用的费用上限和币种。先不充值大额、不提供聊天明文密钥。
2. 在受支持的安全配置位置填写 `DEEPSEEK_API_KEY`。如继续复用仓库运维，可由用户在 GitHub 仓库 Settings → Secrets and variables → Actions → New repository secret 安全填写；不得填写在工作流普通输入框。密钥值不需要给工程对话查看。
3. 主工程师先按现有流程发布兼容 PWA，再用备份优先的 SSH/Actions 路径升级后端，核对旧快照、历史、授权和 AI 收据完全保留。AI 默认保持关闭。
4. 费用批准后再补充并审阅独立的安全启用操作：把密钥传入服务器 root 专用配置，设置 `BANYA_AI_ENABLED=1`、`DEEPSEEK_MONTHLY_BUDGET_USD`、`DEEPSEEK_MONTHLY_CALLS` 和经核对的单价。当前 PR 不包含自动写入密钥或启用付费的工作流。用户不需要手工 SSH 或执行命令。
5. 先核验未授权请求被拒绝及预算保护，再由用户在手机主动授权一笔小范围真实讨论，核对思考模式、JSON 兼容性、响应时间、实际账单、预览和手动确认。缺少这一步不能声称真实 DeepSeek 通道已打通。

后端新增 `ai_requests` 是附加私有表，原快照结构不变。部署升级保护也核对该表；数据库备份含 AI 收据，但不会进入 GitHub。单次建议最多十二项，完成、不做、实际时间、错题和笔记都不允许通过建议改写。
