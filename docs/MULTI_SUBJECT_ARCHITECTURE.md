# 研途 M2.5｜多科目与智能学习界面架构

更新：2026-10-15。本文件是未来接入政治的工程依据，不代表政治计划已经生成。

## 用户确认的产品决定
- “研途”升级为可支持英语二和政治的考研复习PWA。当前英语二已有65天计划、99项专项任务（计划数据仍为M2.3）。
- 政治将加入，但用户尚未提供学习资料、当前学习进度、每天可支配政治时间和备考策略。因此政治只展示**待建档**，不编造真题、课程阶段、已完成任务或目标成绩。
- 用户习惯使用番茄 Todo，**不开发计时器、番茄钟或重复的专注统计**，也不假设能读取番茄 Todo 数据。
- UI要漂亮、有适度动画，但内容优先、移动端流畅、无付费依赖、减少动态效果兼容；保持本地存储及免费 Cloudflare Workers Static Assets 部署。

## 当前多科目设计（M2.5）
- `study-intelligence.js` 中 `SUBJECTS` 是科目注册表，英语为 `active`、政治为 `awaiting-plan`。这里存储的是非个人化项目元数据，不等于用户真实学习进度。
- 当前英语仍从 `plan.json` 和 `plan-data.js` 获取计划；本地记录键 `yantu_english_2026_m1` 及已确认计划键 `yantu_english_plan_v2` **均未更改**。原有打卡和错题仍留在原位置。
- 政治的未来计划文件名称暂定 `politics-plan.json`，未来独立状态键暂定 `yantu_politics_2026_v1`。这些仅是预留命名空间，**现在没有创建政治任务或记录**。不要把英语数据迁移到政治数据。
- 网页主题设置使用新独立键 `yantu_theme_v1`，只保存 `light`／`dark`，不更改学习记录键。
- UI当前在英语、政治之间切换；政治所有页面显示诚实的待建档说明及可复制信息清单。进入政治不会读取/修改英语打卡。
- `study-intelligence.js` 导出纯函数：`recommend(plan,state,Core,day)` 和 `week(plan,state,Core,today)`。推荐仅使用当前实际任务、已打卡状态、错题数和预设题型权重，**不是机器学习模型，也不是AI自动诊断**。不联网、不写数据、不自动修改计划。
- 近七天图表只统计真实打卡；没打卡不等于用户没有学习，完成任务的预计分钟数不等于真正计时。

## 政治正式启用的开发步骤（等待用户实际信息）
1. 用户确认教材/课程/题库、复习到哪一阶段、题库完成度、真实错题情况及每日/每周政治可用时间。不要求一次填完；可以从用户口述开始。
2. 经用户确认后制定可执行的政治计划，设计独立 `politics-plan.json` 数据schema和版本字段，并在单独的政治学科模块里独立校验，不能直接套用现有英语 `planner-core.js` 的固定日期和题型枚举。
3. 专门实现政治状态、迁移、导出/导入、恢复前副本和记录持久化；政治与英语分开备份或可合并导出，但**绝不能覆盖用户原英语备份**。
4. 只有真实计划校验通过、离线缓存资源同步、跨科目UI与统计测试通过后，才能将 `SUBJECTS.politics.status` 从 `awaiting-plan` 改为 `active`。此时同时修订政治预留测试（目前会断言尚无政治计划）。
5. 学习建议的“智能”：明确区分基于规则的本机提醒与ChatGPT基于用户主动反馈的计划修改；不要暗示云端AI正在监视手机学习数据。正式多科目统筹时再考虑英语、政治、数学与专业课的时长权衡。

## 核心兼容性/隐私
- GitHub仓库Private，但公开Workers网址上的HTML、JS和静态计划对外可见。**不把个人做题笔记、账号、Token或身份信息写进静态计划**。
- 不新建Cloudflare项目、不启用可能要求绑卡的Zero Trust/Access、不把学习记录上传公开后端。
- App界面版本 M2.5 与英语日程版本 M2.3 是两个维度。M2.5只升级UI、规则和缓存资源，不修改英语任务ID、日期、内容、planVersion或revision。
- 每次App静态资源更新同步 `sw.js` 的CACHE和ASSETS，并把新增的JS模块加入完整离线资源缓存/模拟测试。旧缓存不得在安装失败时被清掉，不强制`skipWaiting`。
- 主要目标手机是荣耀Android 16、Edge安装PWA。Node与Service Worker模拟通过不等于真实手机视觉/离线/键盘/触摸已验收。
