# 快速修改计划与低负担工作流

用户可在对话里先说清楚要改什么，例如：“把英语二 10 月 20 日的翻译移到 10 月 22 日；保留已有打卡。”无需复制长聊天、运行命令或手动操作 GitHub。讨论不会自动写入手机：执行私人调整需要下述已授权的数据通道。若未指定科目、日期或希望的结果，AI 只问最关键的一项。

如 GPT 额度暂时不可用，备用 API agent 的授权边界、操作步骤和完整任务提示词见 [AI_AGENT_WORKFLOW.md](AI_AGENT_WORKFLOW.md)。

**先区分私人调整和默认模板。** 用户自己的任务、错题、时间和进度应在 PWA 本机记录中修改，经已授权的云快照保存；英语二已有私人任务编辑，政治从 M4.5 起有私人任务增删改。默认静态计划文件仍在公开仓库，它只代表所有用户共用的预设安排。不要为了用户个人调整而修改它，也不要把私人数据贴到 PR、Actions 或仓库文档。

普通 GPT／项目对话及 GitHub 连接器目前没有服务器私人数据授权。M5 受限 GPT Action 通道已部署，仍待用户一次性安全接入，不能把部署说成私人安排已同步。完成接入后，日常私人任务调整可以直接走服务器数据接口，不创建公开 PR 或重新发布软件。权限、版本保护和真实接入边界见 [PRIVATE_PLAN_ACCESS.md](PRIVATE_PLAN_ACCESS.md)，不能复用手机的全量同步密钥。

下一阶段日常入口使用同一 PWA 内的 DeepSeek 思考助手：同步手机记录 → 选科目和日期讨论 → 看具体建议 → 用户确认 → 事务备份与版本校验 → 手机接收。M6 仍在开发待审，付费默认关闭，真实密钥、预算批准与上线验收尚未完成。分工、费用和隐私边界见 [DEEPSEEK_ASSISTANT.md](DEEPSEEK_ASSISTANT.md)。

只有用户明确要求改变所有设备共用的默认模板，执行者才按下列 GitHub 发布流程完成：

1. 读取最新 `main`、`AGENTS.md`、本页和开放 PR；只读取本次涉及的科目文件，不重读整个项目历史。
2. 核对旧任务 ID、日期、时长与相邻任务；仅改用户要求的计划，保留其他科目和旧记录。需要个人实际进度时向用户确认，不从公开计划或旧 Git 文档推断。
3. 编辑对应 JSON，更新该科版本/修订号与简短变更摘要；运行 `node scripts/sync-plan-mirrors.mjs --write english` 或 `--write politics` 自动更新离线镜像。如变更影响缓存，再更新 `sw.js`。
4. 运行计划检查、相关科目和跨科回归、隐私检查；创建简短 PR。仅在获得合并与发布授权后操作；日常发布只核对 ECS，历史 Worker 保留恢复，不再作为前置发布。
5. 给用户一条简短结果：改动日期和任务、版本、日常入口的线上状态、手机是否仍需确认。不要把代码日志或长篇项目历史发给用户。

每次独立需求用一个新对话和一个短 PR，有助于减少长对话卡顿。GitHub 文档保留稳定的工程规则；当前个人学习近况不写进公开仓库。对话卡住时在同一 GPT 项目开新对话，直接说“继续板牙考研，先读最新 main 和 AGENTS.md；本次要改……”。

云同步、离线恢复和存储改动需先分别保护英语二与政治备份；不能静默覆盖。自动测试、Cloudflare 发布、手机实测分别报告。若 Cloudflare PR 预览构建失败，先核查同一提交的 GitHub 检查、构建日志与本地 dry-run，不能把预览失败误称为正式网站宕机。

M7.1 起，长期目标和要求可以通过原 App 的「学习档案与规则」管理，只更新私有档案，不改公开默认计划或打卡。模型不能自行把聊天写成长期规则。档案、上下文、能力契约的开发验收及待授权导入见 [M7_1_MEMORY.md](M7_1_MEMORY.md)；尚未上线。

工程精简后，以 [ECS_RELEASE.md](ECS_RELEASE.md) 为发布规范。Cloudflare 外部检查不作为日常验收条件，不主动诊断；历史文档中的双平台发布描述仅为旧事实。

M7.2 的诊断在本人主动打开时使用免费确定性服务；日、周和阶段建议经明确数据/费用授权才允许请求模型，当前尚未启用真实服务。M7.2 只预览，不触发原提交或自动执行，详见 M7_2_PLANNING.md。工程日常只验收 ECS，不为 Cloudflare 外部构建追加诊断。
