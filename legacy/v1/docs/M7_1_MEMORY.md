# M7.1：学习档案与上下文基础

M7.1 从 PR #53（`60517e9`）建立独立阶段 PR，以 #53 分支为基线审阅。没有合并、部署、读取生产记录或调用真实 DeepSeek。这里只保存和组织「AI 应该知道什么」，不增加自动调整计划、授权自动执行、定时任务或开发工具。

## 手机入口

原 PWA「设置 → 学习助手 → 学习档案与规则」。不要求启用付费模型，可查看目标、历史基础、资料、预算、偏好、硬性要求和进度说明；编辑、停用或重新启用，查看来源及最近旧版本。历史基础与真实打卡分开。编辑数值后界面也显示这些数值，避免只看旧文字说明。

保存只更新档案，不能修改计划、打卡、错题或实际时间。服务器已有新版本时停止覆盖；结果不明可重试同一个请求 ID。退出后重新进入会读取服务器当前档案，不在手机另存第二份档案数据库。离线时不能保存服务器档案；原 App 打卡与离线同步机制保持不变。

## 数据结构与版本

沿用同一个 SQLite 文件，新增四张私有表：

| 表 | 用途 |
| --- | --- |
| `learning_profiles` | 按科目保存当前 schema、独立递增 revision 和档案文档 |
| `learning_profile_history` | 每次保存前的完整档案；以科目和旧 revision 唯一定位，初始空档案也备份 |
| `learning_profile_requests` | 科目内请求 ID、请求哈希和结果收据，防重复及 ID 碰撞 |
| `learning_summaries` | 预留摘要 schema、档案/快照版本、来源、有效期及摘要字段；本阶段没有写入接口、生成任务或使用旧摘要的逻辑 |

档案 schema 为 `1`，独立于 PWA 缓存、代码 SHA、计划模板和快照版本。初始化仅创建空表，重复运行不改原行；软件升级不会导入默认学习档案。当前没有跨 schema 数据转换：遇到不支持版本会拒绝相关操作，不能默默重置或猜字段。

每条条目包括：

- 稳定 `key`、`category`（goal/history/material/budget/preference/constraint/progress）及 `active`。
- 结构化 `value`：说明文字，以及按需填写的分钟、目标上下限、考试年份、资料拥有情况、数量及总量。空值不是零。
- `source.kind/reference`、服务器保存时的 `confirmedAt`、`entryRevision`。这里的确认时间表示本人保存档案的时间，不证明自述事实得到独立核实。
- `certainty`：confirmed/reported/estimate/unknown；`temporal`：current/historical；`observedOn`、`validUntil`。
- `topics` 为有限题型/学习方式标签，用于选择相关背景；无标签视为 general。
- `sensitivity`：standard/review。错题或复盘类档案需要额外勾选分享。硬约束必须已确认且不包含该类敏感细节。

历史条目必须有资料日期，history 类不能标为当前。当前非未知的进度说明必须有观察日及有效期，过期后标为 `expired_unknown`。例如某部分题库曾有一个历史比例，而现在进度未知，应分别保存为历史快照和未知说明，绝不把历史比例当作整科当前进度。

同一规则维度使用同一个 key；新值替代当前值，完整旧文档留在历史中。不同 key 的自然语言矛盾不由服务器猜测消解，应由本人修正或后续分析提示。停用不会删除历史。上限为每科 80 条、文档 60 KB，避免无界提示词和误存原始聊天。

## 所有者接口

均在已有 `/v1/ai/` HTTPS 反向代理下，沿用所有者认证、禁止缓存、关闭私有 API 访问日志。GPT Action 的受限访问钥匙不能调用这些所有者接口。

| 接口 | 行为 |
| --- | --- |
| `GET /v1/ai/profiles/{subject}` | 当前档案，未初始化返回 revision 0、空条目 |
| `POST /v1/ai/profiles/{subject}` | 初始化或按 key 增改/停用；严格 schema、requestId、expectedRevision、entries、confirmation=`save_profile` |
| `GET /v1/ai/profiles/{subject}/history?before=...` | 每页 10 个旧版本，返回 nextBefore |
| `POST /v1/ai/context` | 免费、只读、确定性地生成上下文 |
| `GET /v1/ai/capabilities` | 当前可用只读能力契约 |
| `POST /v1/ai/read` | 按能力 ID/版本和严格参数调用允许的只读实现 |

档案保存使用 `BEGIN IMMEDIATE`：先比较版本，再备份完整前像，再保存新档案与请求收据，任何一步失败则事务回滚。只合并本次指定 key，不允许替换整个学习快照、删除历史或接收任意字段。读取上下文在同一个 SQLite 读事务中取一致视图。原快照结构、存储键和核心同步协议没有变化。

现有升级打包路径包含新模块；手动升级脚本在停止写入并核验私有数据库备份后，仅初始化附加空表，恢复服务前比较所有旧表。`upgrade_guard` 已包含四张档案/摘要表。**修改脚本不代表运行过升级，本阶段未运行。**

## 上下文选择与预算

`context_engine.build_context` 与模型网络调用分离；`ContextRequest` 定义请求。即使付费功能关闭，所有者仍可生成上下文验收。

优先级：服务器安全规则 → 最新有效硬约束 → 当前目标与背景 → 最新真实云快照 → 相关统计与任务 → 必要对话。

- 默认按科目隔离。`purpose=day` 使用目标日 ±1 天；`week` 默认最近 14 天与未来 7 天；普通讨论使用有限窗口，也支持显式最多 31 天的选择。日期限制约束讨论数据，不是长期规则有效期。
- 背景先按显式 focusTags、问题中的题型或所选任务类型筛选；历史基础最多取普通讨论4条、周分析8条、单日3条，报告省略数。硬约束不受相关性筛选影响。
- 最近表现按任务所属日期汇总已保存的完成、不做和实际时间样本；明确不是实际完成日期统计。缺失时间保持未知，未记录不证明没学习；没有独立当前整体进度就标未知。无法定位日期的记录只报数量，不猜所属日。
- 默认模板说明不当成个人证据，不发送其中的历史叙述。任务只取必要身份、状态、预计时间与真正保存的实际时间；私人说明限制 240 字，额外授权的错题题号/复盘各限制 500 字，并标记截断。
- 只有 `coordinateSubjects` 加 `crossSubjectConsent=true` 才读取另一科必要的近期数量/时间摘要；不发另一科任务、档案正文、错题或笔记。仅靠对话文字或模型输出不能开启跨科授权。
- 档案中当前有效的结构化时间预算优先于旧同步设置，附带来源。原 M6 写入校验的安全上限保持原样，本阶段没有新建计划自动执行器。
- 输出包含 contextVersion、profile schema/revision、条目来源及版本、快照 revision/updatedAt、模板版本/哈希、截断计数和所用预算来源。历史、估计、未知、过期资料分别标注。
- 默认输出上限 24 KB，可测试范围 4–28 KB，以 UTF-8 紧凑 JSON 计。最多 100 项任务、6 条对话，每条最多 2000 字。先丢旧对话，再丢低优先背景，再压缩可选私人说明；不删安全规则、当前有效硬约束、所选任务身份/状态/实际时间或最后一条请求。仍超限返回 413，调用模型前停止。不会为了凑长度把缺失数据补出来。
- 不保存原始聊天或模型内部推理作为档案，也不调用模型生成摘要。模型输出不能变成新规则；需要本人在档案中明确保存。

PR #53 原有聊天路径改用这个上下文引擎，仍要求主动付费授权、配置及预算。授权文案包含所选科目的档案与规则；错题/复盘仍需额外勾选。建议生成期间、预览之后若档案规则版本变化，旧建议失效。原有手动预览和确认机制保留，不新增自动执行。

## 只读能力契约

`capabilities.REGISTRY` 为后端控制的版本化允许列表，目前只有：

- `learning.profile.read@1`
- `learning.context.build@1`

契约由实际 Pydantic 参数模型生成输入 JSON Schema，同时列出返回结构、只读属性、适用科目、owner:read 权限、profile schema 与 contextVersion 兼容要求以及启用状态。实际执行通过固定 IMPLEMENTATIONS 映射，不能给出路径、函数名、Shell 命令或任意 HTTP 地址来调用其他能力。

撤销、缺少实现、不兼容或档案迁移不完整会拒绝受影响的操作；无效能力不会暴露给模型。CI 检查注册列表和实现集合一致、输入模型及输出必需字段与真实调用结果一致，并检查撤销/不兼容拒绝。开发增删能力时必须同时维护契约和实现。

档案修改是用户界面使用的所有者接口，不注册为模型写能力。清单没有 SSH、GitHub、源码、部署、密钥、历史记录写入或自动计划修改能力。

## 初始私有档案导入

用户给出的真实资料已整理为**仓库外、权限 0700 目录中的 0600 私有草稿**，并用同一 Entry 模型校验；没有提交、公开展示或入库。草稿 expectedRevision 和 confirmation 均未填写，不能直接提交。对话中提到的历史完成情况仍只作用户报告的基线，不生成 done、wrong 或 actualMinutes 等打卡字段；过时或更正的叙述不能自动成为当前事实。

后续导入必须在用户授权后：读取当前科目档案版本 → 本人核对条目/来源/不确定性及分享标记 → 用新的 requestId 和该 expectedRevision 调用所有者接口 → 确认备份收据。出现冲突先核对，不覆盖。草稿不依赖 GitHub 或 Actions 参数传输，也不需要重新导入旧备份；当前环境私有草稿不等于已持久保存到服务器，迁移环境前需安全接续。

## 验证和范围边界

本轮本地 138 项 Node、89 项 Python 测试通过；计划及镜像检查、脚本语法、隐私检查和 Worker dry-run 通过。测试存在现有 Starlette TestClient 的弃用提示，不影响通过结果。自动化使用合成数据和禁用/模拟提供商，覆盖档案重启与升级保留、历史版本、幂等、冲突、备份失败、旧新规则、未知进度、双科与跨科授权、上下文安全裁剪、来源、能力撤销/兼容、模型内部思考不入库以及原云同步/学习记录回归。本地手机尺寸 Chromium 连接真实后端代码验证档案查看、编辑、停用、只读历史、切科和关闭重开；学习快照没有变化，也无模型请求。

Cloudflare 独立检查在本阶段之前已失败：#53 的 `60517e9` 是 failure，但同提交 GitHub Validate 和 Worker dry-run 成功；main `faac256` 的正式 Workers Build 成功。GitHub 检查仅给出 Cloudflare 控制台 Build ID，没有错误正文，故**具体平台原因未确定**，不能归因于档案改动或宣称已修复。没有扩大范围修改构建平台设置。

未验证：生产迁移/保留、真实 DeepSeek 兼容与计费、真实手机 Android 行为、本人档案导入。本阶段不需要密钥，也不启用付费。

## M7.2 可复用的部分

直接复用 schema 1 档案、key/entryRevision 历史、幂等保存和前像备份、ContextRequest/build_context、来源与裁剪报告、版本化只读能力及原 M6 预览/CAS/备份。`learning_summaries` 预留后续带来源摘要格式，但不把占位表当成已有摘要生成能力。

任何未来自动规划、预授权执行、摘要生成或新写能力都需要下一阶段单独设计、权限审阅和测试；M7.1 不实现 M7.2–M7.4。
