# M7.4 跨阶段集成与上线前演练

本阶段没有合并或部署，没有打开生产 SQLite、读取私人快照、导入真实档案、安装密钥或调用付费模型。所有数据库、记录和模型都为临时合成夹具。

## 实际修复

- 快照请求拒绝 HTTP 重定向，并显式不附带无关浏览器凭据。
- GET 等待期间手机出现新记录，会停止旧记录上传。接收云端时先计算指纹并再次核对本机，再同步写入记录和版本，消除异步计算期间覆盖新输入的窗口。
- 支持 StorageEvent 的浏览器同步更新内存任务状态，避免旧页面在刷新前保存旧覆盖层；不再让整页 reload 与弹层 history.back 竞争。旧浏览器保留刷新兜底。英语和政治采用一致的弹层关闭处理。
- 两科自动队列轮转选取，某科冷却或限额不会让另一科永久等待；权限、冷却、版本、次数与费用仍逐项检查，轮转状态不授予任何权限。
- SQLite 临时备份立即采用0600，并在发布文件及清理旧备份前验证完整性；备份失败保留原可恢复副本。
- ECS 同 SHA 重跑先比对完整成员和字节，完全相同且线上核验通过才视作已发布；不同内容拒绝覆盖。失败时隔离本次新建的公开静态目录，恢复旧链接/配置，允许干净重试；不替换数据库。

## 分层验证

1. `scripts/validate.sh`：完整 Node、Python、隐私、双科、认证、能力清单、预算、CAS、备份与 ECS 包校验。
2. `scripts/visual_acceptance.py`：72张合成截图，三种尺寸、双科6组场景；本地真实后端/注入模型，视觉层使用测试绑定，不能替代云同步传输验证。
3. `scripts/integration_browser.py`：不替换 BanyaCloudSync 方法，执行真实前端请求和 localStorage 同步逻辑。拦截全部 HTTPS 请求并交给本地 TestClient，绝不访问真实 ECS；Service Worker 在此独立传输场景关闭，其离线缓存由视觉套件另测。

真实模块演练：手机新增笔记 → 实际 CAS 上传触发事件 → 免费检测 → 模拟规划 → 事务备份及未来覆盖层提交 → 手机收取 → 撤销并收取 → 离线编辑与另一设备并发修改 → 停止冲突覆盖。英语和政治各通过一轮；每轮1次注入模型调用，真实付费次数0。实际时间、错题、完成/不做与笔记保持原值。

4. `test_m74_rehearsal.py`：从公开 M5 初始化函数对应的表结构建立合成旧库，生成私有备份，重复初始化全部附加表，核对旧快照/历史原样保留。受认证初始化合成档案，历史基础不变为打卡；能力只读；默认 AI 与自动管理关闭。服务重启后档案保留，并从备份恢复到独立副本验证，不覆盖现库。
5. ECS 沙盒运行实际静态发布脚本：验证失败回滚、同 SHA 重试/重复运行、内容篡改拒绝；数据库字节保持不变。后端升级沿用现有匹配 PWA SHA 前置条件、停写备份、附加表检查和代码/配置回退，不创建第二套发布系统。
